# ADR-001: FitFlow High-Level Technology Architecture

## Status

Accepted

## Context

FitFlow needs a cross-platform application, AI-powered personalization, camera-based nutrition processing, private social features, real-time updates, secure data management and scalable infrastructure.

## Decision

Use React Native and React/Next.js for clients; NestJS for the core API; FastAPI for specialized AI/ML; PostgreSQL for primary data; Cognito for authentication; Redis for caching/realtime support; S3 and SQS for files and asynchronous processing.

## Rationale

The architecture separates core transactions from AI workloads, supports cross-platform delivery, uses relational data storage for interconnected records and provides clear security and scaling boundaries.

## Alternatives

Flutter, Kotlin Multiplatform and Swift/SwiftUI; Express, FastAPI, Go and Spring Boot; MongoDB, Firestore and DynamoDB; Firebase Auth, Auth0 and Supabase Auth.

## Consequences

Improves modularity and independent scaling but introduces multiple services that require configuration, monitoring and maintenance.

## Risks

Dependency changes, cloud complexity and growing AI workloads.

Mitigations include version pinning, managed services, monitoring, API contracts and independent AI scaling.
